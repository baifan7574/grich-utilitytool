# 第一部分：AI 行为总纲 (Agent Behavior Rules)
1. **上下文优先**: 开始前必须检查根目录 `status.md` 了解项目最新进度。
2. **技能合规**: 修改代码前必须对照本 SKILL 规则，严禁违规操作。
3. **环境预检**: 必须读取根目录 `.env`，若缺少 Token 立即停止并报错。
4. **自我更新**: 完成重要任务（如更新了 1.9 万页面的模板）后，必须更新 `status.md`。
5. **中文回复**: 始终使用中文与用户沟通。

# 第二部分：核心章节 (rules)

### 第 0 章：真实性与零冗余纪律 (No-Nonsense Protocol)
- **0.1 禁止模拟成功**：Agent 严禁在未经过本地测试（Dry Run）的情况下声称“已修复”或“已跑通”。任何结论必须基于物理执行结果，而非逻辑推测。
- **0.2 拒绝“老师腔”**：严禁使用任何谄媚、说教或虚假的鼓励话术。对话必须保持专业、中立、冷峻，直接给出数据和结论。
- **0.3 故障优先披露**：如果任务失败，Agent 必须在回复的第一句话就说明“失败原因”和“报错行号”，严禁将问题掩盖在长篇大论的解释中。
- **0.4 零水分原则**：去掉所有无意义的开场白（如“我非常理解您的顾虑”）。直接说：做了什么、发现了什么、下一步怎么做。

### 第 1 章：内容风控 (Thin Content)mplate-First)
- **1.1 禁止直改产物**：严禁直接手动修改 `dist/` 目录下的 HTML 文件。
- **1.2 溯源修改**：所有视觉或内容变动必须通过修改 `step2_site_builder.py` 里的字符串模板或 `csv` 源数据实现。
- **1.3 构建验证**：修改模板后必须重新运行构建脚本，并抽检 `dist/` 产物是否符合预期。

### 第 2 章：数据驱动优化 (Data-Driven Optimization)
- **2.1 关键词注能**：自动从 GSC 获取过去 7 天内“高印象、低点击（<1%）”的词。
- **2.2 循环反馈**：将上述词汇反馈给 `step1_data_miner.py` 或直接更新 `professions.csv` 中的描述字段，优化页面 Meta 标签。

### 第 3 章：结构与内容进化 (SEO Growth)
- **3.1 内链织网**：在 p/ 目录下，自动根据“职业/行业相关性”插入 5 个互联链接，构建蜘蛛网状结构。
- **3.2 内容加厚**：针对排名在 11-20 位的潜力页面，调用 AI 自动生成 300 字左右的专业合规建议段落，增强页面权重。

### 第 4 章：防降权与质量卫士 (Anti-Deindexing)
- **4.1 动态差异化 (Dynamic Randomization)**：
    - Agent 在修改模板时，必须引入“随机段落”机制。
    - 严禁 1.98 万个页面使用完全相同的描述文字。每个页面的描述必须根据 `csv` 数据进行差异化组合。
- **4.2 内容长度监测 (Thin Content Guard)**：
    - 自动检测生成的 HTML 正文长度。若核心文字内容少于 400 字，Agent 必须提示并自动调用 AI “加厚”该分类的内容。
- **4.3 独特性校验 (Uniqueness Check)**：
    - 在批量生成前，随机抽检 3 个页面的相似度。
    - 若文本重复率超过 80%，Agent 必须停止构建，并重新设计 `step2_site_builder.py` 中的拼接逻辑。
- **4.4 用户体验预警 (UX Audit)**：
    - 监控 TailwindCSS 加载情况，确保变现代码（广告位）不阻塞主工具（PDF 处理）的交互。
